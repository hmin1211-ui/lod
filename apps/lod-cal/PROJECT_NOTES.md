# 어둠의전설 데미지 계산기 진행 기록

## 현재 상태

- 정적 웹앱으로 구현됨: `index.html`, `styles.css`, `app.js`.
- 원본 엑셀 `E:\OneDrive\데미지계산기-최종.xlsx`의 `크래셔`, `메테오` 탭 수식을 기반으로 구현.
- 로컬 서버 예시:
  - PC 내부: `http://127.0.0.1:5173/`
  - 같은 내부망: `http://192.168.0.53:5174/`
- 외부 공개 배포는 Vercel `lod-cal` 프로젝트로 관리. GitHub 브랜치는 `lod-cal`을 기준으로 한다.

## 데이터 저장 정책

- 기본 입력값은 브라우저 `localStorage`에 자동 저장.
- 같은 브라우저/같은 주소에서 다시 열면 자동 복원.
- 브라우저/PC 간 이동을 위해 상단에 `내보내기`, `불러오기` 버튼 추가.
- `내보내기`는 JSON 파일 다운로드, `불러오기`는 JSON 파일을 읽어 현재 브라우저 localStorage에도 저장.

## 공통 UI 결정

- 상단 결과 제목은 `데미지 계산`.
- 데스크톱 입력 영역은 좌측 세로 입력표, 우측 데미지 계산 표 구조.
- 가중치 카드는 같은 높이로 맞춤.
- 가중치 카드:
  - `AC가중치`: 실제 가중치가 아니라 `AC 변화량 합계` 표시. 표시값은 합계에 `-1`을 곱함.
  - `데미지증가`
  - `버프가중치`
  - `핫타임`
- `AC가중치` 카드 하위 항목에서 `기존 AC`는 제외.
- `핫타임`이 Off라서 가중치가 1이면 카드와 결과표에 `-`로 표시.
- `기존 AC` 컬럼은 흰 배경으로 표시.
- 컬럼명과 몬스터명은 가운데 정렬.
- 내보내기/불러오기 버튼은 탭 버튼 상단에 별도 줄로 배치.
- 몬스터 추가는 목록 하단 `몬스터 추가` 버튼으로 실행.
- 몬스터 목록 하단에 `순서 변경` 버튼 있음.
- `순서 변경` 모달에서 장소별 `▲`, `▼` 버튼으로 표시 순서를 변경.
- 장소 순서는 탭별로 localStorage와 JSON 저장/불러오기에 포함.
- 신규 장소는 해당 탭 장소 순서의 마지막에 자동 추가.
- 버튼을 누르면 입력 모달이 열림.
- 몬스터 추가 입력 정보:
  - 장소
  - 몬스터명
  - AC
  - 체력(선택)
- 사용자가 추가한 몬스터만 삭제 가능. 기본 몬스터는 삭제 버튼 없음.
- 추가 몬스터는 localStorage와 JSON 저장/불러오기에 포함.
- 체력 정보가 있는 추가 몬스터는 샷 판정 표시.

## 무도가 탭 결정

- 무도가 탭은 전사 탭과 몬스터/장비/가중치 입력 구조를 공유하되 전직 항목은 사용하지 않음.
- 무도가 집중은 전사와 별도 처리:
  - `Off = 0`
  - `일반 = 0.3`
  - `업글 = 0.4`
- 무도가 집중은 다라, 구양, 선풍, 붕각, 단각, 지열 전체에 적용.
- 무도가 기술 기본값은 모두 `업글`.
- 다라는 일반/업글 구분 없이 항상 계수 `2`로 계산하며, 입력 선택 항목은 표시하지 않음.
- 다라와 구양은 어빌 환산값 영향을 받지 않음.
- 구양은 다라처럼 선택 항목을 표시하지 않고 항상 계수 `0.4`로 계산.
- 단각/붕각/선풍/지열의 `업글` 계수:
  - 단각: `20.81838`
  - 붕각: `30.52726`
  - 선풍: `19.423302`
  - 지열: `23.25`
- 단각/붕각/선풍/지열의 `업글` 환산값은 전사 퓨리 업글과 동일하게 `업글 계수 * 어빌환산값`으로 표시/계산.
  - 이때 어빌환산값 보정률은 퓨리 업글과 같은 `0.00415`.
  - 어빌이 `201` 미만이면 어빌환산값은 `1` 고정.
- 단각/붕각/선풍/지열이 `업글`이 아닌 숫자 레벨일 때는 `기본 계수 * 선택 숫자`로 환산값을 계산.
  - 다라/구양은 선택 항목을 표시하지 않고 이 숫자 레벨 곱 규칙에서 제외.
- 업글 계수가 아직 없는 기술은 일반 계수와 같은 값으로 처리.
- 입력 패널의 `저장` 버튼은 현재 입력값을 브라우저 localStorage에 저장.
- `장비 - 에테르 강화 수치 입력` 카테고리에 `이펙트`, `호드/나겔목` 포함.
- `이펙트` 환산값은 악세와 동일하게 `(강화수치 + floor(강화수치 / 5)) * 0.01`로 계산.
- `호드/나겔목` 선택값은 `Off`, `호드목`, `나겔목`.
  - 기존 저장값 `On`은 로드 시 `호드목`으로 변환.
  - `호드목` 환산값: `0.15`
  - `나겔목` 환산값: `0.3`
- `마나감소` 스펙 입력칸 오른쪽에는 회색 단위 `%` 표시.
- `아크`, `아브`: 0~3 선택형.
- `기습`: On/Off 선택형. On이면 환산값 20, Off면 0.
- `움`은 `움(렙)`으로 표기, 0~6 선택형.
- 배포용 기본 데이터는 개인 테스트값을 넣지 않음.
  - 크래셔/메테오 `어빌`: `201`
  - 크래셔 `무장체`, 메테오 `무장마`: `1000000`
  - 크래셔 `힘`, `콘`: `180`
  - 그 외 숫자 입력 기본값: `0`
  - 선택 목록 기본값: 첫 번째 항목. `On/Off` 목록은 `Off`가 첫 번째.
- 크래셔 `무장체` 환산값 칸에는 `추뎀` suffix를 표시하고, 수동 수정값은 `convManual.basePhysical`에 자동 저장.
- 크래셔 `힘`, `콘`은 환산값 칸을 표시하지 않음. 저장된 수동 환산값도 로드 시 제거.
- 크래셔 탭에는 `전직` 항목 있음. 선택값은 `순수`, `도전`, `직전/법전`.
- `전직` 환산값은 표시 전용으로 `순수=4`, `도전=2`, `직전/법전=2`.
- 크래셔 데미지 컬럼 공식의 기존 고정 계수 `2`는 `전직` 환산값을 참조.
- 크래셔 `기술` 카테고리에 스킬 설정 입력:
  - `매드`: `일반`, `업글`
  - `퓨리`, `대쉬`, `내려/사방`: `0`~`10`, `업글`
- `매드` 환산값:
  - `일반`: `0.5`
  - `업글`: `0.545 * 어빌 환산값`
- `퓨리` 환산값:
  - 숫자: `4.984914075823167 * 숫자`
  - `업글`: 기존 퓨리 공식 계수 `84.522023673402`
- `대쉬` 환산값:
  - 숫자: `3.724984600805496 * 숫자`, 표시값은 소수점 둘째 자리까지
  - `업글`: `37.25` 임시값, 정확한 값 확인 필요
- `내려/사방`은 현재 선택값 저장/복원만 적용. 세부 공식 연결은 후속 요청 기준으로 적용.
- 메테오 탭에는 `전직` 항목 없음.

## 크래셔 탭

- 결과 그룹:
  - 나겔링
  - 보스
  - 연습장
- 크래셔 발록은 유지.
- 발록의 각 기술 데미지는 마지막에 `무장체` 환산값의 체력비례 추가데미지를 더함.
- 결과 컬럼:
  - 몬스터
  - 기존 AC
  - AC변화
  - AC가중치
  - 데미지증가
  - 버프가중치
  - 핫타임
  - 퍼센트
  - 매드
  - 크래셔
  - 퓨리
  - 합계
  - 비고
- `매드`, `크래셔`, `퓨리`는 굵은 글씨.
- `합계`는 녹색 굵은 글씨만 사용. 강한 배경 강조 금지.
- `전직`이 `순수`일 때 기존 `크래셔` 컬럼명은 `데빌`로 표시.
- `퓨리` 뒤에 직업별 추가 데미지 컬럼 있음:
  - `순수`: `대쉬`
  - `도전`: `암살`
  - `직전/법전`: 추가 컬럼 없음
- `매드` 데미지 공식은 `매드` 환산값을 계수로 쓰며, 어빌 환산값을 별도로 다시 곱하지 않음.
- `암살` 공식은 `매드` 공식에서 계수만 `0.375`로 쓰고 어빌 환산값은 곱하지 않음.
- `암살`은 집중 영향을 받지 않으므로 버프가중치에서 집중 계수만큼 제외해 계산.
- `대쉬` 공식은 `퓨리` 공식에서 계수만 `대쉬` 환산값으로 변경.
- `합계`는 `순수/도전`일 때 `매드 + 크래셔/데빌 + 퓨리 + 암살/대쉬`, `직전/법전`일 때 `매드 + 크래셔 + 퓨리` 기준.
- 발록 비고는 크래셔 탭에만 유지.
- 핫타임 옵션은 메테오와 동일하게 `Off`, `평일`, `주말`.
  - Off: 0
  - 평일: 0.15
  - 주말: 0.2

## 메테오 입력 특이사항

- `마나감소`는 `장비 - 에테르 강화 수치 입력` 카테고리로 이동.
- `마나감소`는 귀걸이 위에 배치.
- `마나감소`는 AC가중치와 무관하므로 AC변화/AC 변화량 합계에서 제외.
- 단, 데미지 공식에는 계속 적용.
- 별도 `1틱`, `1틱+메디` 행은 제거.
- `무장마` 행의 환산값 칸에는 `floor(무장마 / 5 * (1 + 귀걸이 환산값))` 공식 결과를 표시.
- `무장마` 환산값 칸은 공식 결과 표시 전용이며, 기존 저장 데이터의 수동 `oneTick` 값은 로드 시 제거.
- `1틱` 환산값은 `메디` 행의 환산값 칸에 표시.
- `무장마`, `메디` 행의 환산값 칸 오른쪽에는 회색 `1틱` 라벨 표시.
- 기존 `메디` 환산값은 메디 아래 보조 입력:
  - `메디 회복량 : [입력칸]`
- 기존 `1틱+메디` 값은 그 아래 보조 입력:
  - `1틱 + 메디 : [입력칸]`
- 두 보조 입력은 수정 가능하고 계산에 반영.
- 코드의 `c.castMana`는 화면의 `1틱 + 메디` 입력값이 아니라 마나감소 기준값.
  - 모든 메테오 데미지 컬럼에 공통으로 들어가는 시전마나이며 `12960`으로 고정.
  - 데미지는 `입력 마나 - 12960 * 마나감소환산값`을 기준으로 계산.
  - `마나감소` 옵션이 있으면 실제 차감되는 시전 마나가 줄어 데미지가 증가.
  - 저장/불러오기 데이터에 남아있는 `convManual.oneTickPlusMedi`는 로드 시 제거.
- `메디 회복량`, `1틱 + 메디` 라벨은 항목 글자와 동일 크기/굵기.
- `:` 위치와 입력칸 시작 위치는 두 줄 모두 동일하게 정렬.

## 백유 몬스터 정보 팝업

- 메테오 탭의 `백유` 장소명 옆에 `몬스터 정보` 버튼 표시.
- 버튼 클릭 시 `백유 몬스터 정보` 팝업 표시.
- 데이터는 사용자가 첨부한 백작유리드 이미지 표 기준으로 정리.
- 컬럼:
  - `존`
  - `네임`
  - `HP`
  - `DEF Nature`
- `Exp` 정보는 팝업에서 제거.
- 몬스터 정보 팝업의 글자는 두 줄로 밀리지 않도록 `nowrap` 기준으로 표시.
- 10~11존 행은 이미지의 빨간 강조 영역을 따라 은은하게 강조.
  - 10존: 큐립스, 엘리자벳, 큐레스
  - 11존: 엘리자벳, 조안, 큐립스

## 방어율 / AC가중치 공식

두 탭 모두 `AC변화` 기준으로 엑셀 방어율 구간식 적용:

- `저주`의 `데프` 환산값은 크래셔/메테오 모두 `50`.
- 기존 브라우저 저장 데이터에 남아 있을 수 있는 크래셔 `데프=60` 수동 환산값은 로드 시 자동 제거.
- `AC >= -98`: `1 + AC / 100`
- `-196 <= AC < -98`: `(198 + AC) / 5000`
- `AC < -196`: `(296 + AC) / 250000`

이 결과가 각 몬스터 행의 `AC가중치`에 들어감.

## 어빌 환산값

- 크래셔/메테오 모두 어빌이 201 미만이면 환산값은 `1`로 고정.
- 어빌이 201 이상일 때만 각 탭의 기존 환산 공식 적용.

## 허수아비 역산 카드

- 탭 순서는 `허수아비`, 한 칸 띄우고 `전사`, `무도가`, `메테오`.
- 전사/무도가/메테오 탭처럼 왼쪽 입력 패널에는 허수아비 스펙을, 오른쪽 결과 패널에는 `허수아비 역산`과 `기술 계수 추정` 카드를 배치.
- 허수아비 탭 버튼은 전사/무도가/메테오 묶음과 구분되는 별도 버튼처럼 보이도록 스타일링.
- 허수아비 역산/측정 카드의 입력 필드와 체크박스 묶음은 고정 컬럼 대신 화면 폭에 맞춰 자동 줄바꿈.
- 허수아비 탭은 전사/무도가/메테오 탭과 분리된 자체 입력값을 사용.
- 허수아비 입력값은 기술 레벨 입력을 제외하고 `어빌`, `무장체`, `무장마`, `무기 민뎀`, `무기 맥뎀`, `힘`, `콘`, `덱스`, `인트`, `DAM`과 장비/AC가중치/버프가중치/기타 항목을 포함.
- `DAM`은 데미지증가 가중치가 아니라 힘/콘/덱스/인트처럼 기술 계수 측정에 사용할 수 있는 별도 스탯이다.
- 허수아비 집중 선택지는 `Off`, `집중(전사)`, `변신마스터`, `정신집중(도가)`이며 환산값은 각각 `0`, `1`, `0.3`, `0.4`.
- 허수아비 입력 카드 최상단에는 `전사`, `무도가`, `메테오` 입력값 불러오기 버튼이 있음.
- 불러오기는 선택한 탭과 허수아비 입력에 공통으로 존재하는 스펙/장비/가중치 항목만 복사하고, 허수아비 전용 항목은 유지.
- `전사`에서 불러올 때 `집중 On`은 허수아비에서도 `On`으로 유지해서 전사식 집중 환산값 `1`을 쓸 수 있게 함.
- 허수아비 탭 상태(`dummy.specs`, `dummy.specManual`, `dummy.convManual`, `dummy.reverse`, `dummy.coefficient`)는 localStorage와 JSON 내보내기/불러오기에 포함.
- 허수아비 역산 카드에는 별도 `계산식` 선택을 표시하지 않음. 허수아비 자체 입력값과 공통 물리 속성 공식으로 계산.
- `기술 계수 측정` 카드를 추가.
  - 특정 직업/기술 선택 없이 허수아비가 입은 데미지를 입력하면 허수아비 타격 조건의 AC/버프/핫타임/정령을 제거해 `원 데미지`를 구함.
  - UI는 `측정값`, `스탯 조건`, `가중치`, `계산 결과` 묶음으로 배치.
  - 측정 속성은 `생암`, `암암`, `속암` 중 선택. 내부 계산은 각각 `생암`, `암암(반속)`, `암방` 공식에 연결.
  - 반영 스탯은 `힘`, `콘`, `덱스`, `인트`, `DAM` 체크박스로 선택.
  - 스탯 관계는 `곱연산` 또는 `합연산` 중 하나를 선택.
  - `어빌가중치 적용` 체크 시 최종 분모에 허수아비 어빌 환산값을 곱함.
  - 추정 계수 공식: `원 데미지 / (선택 스탯 연산값 * 어빌가중치)`.
  - 계수 측정 카드에는 역산 카드와 별도의 `AC가중치 적용`, `버프가중치 적용`, `핫타임(%)`, `정령 %` 조건이 있음.
  - 계수 측정 조건은 `dummy.coefficient` 하위에 저장되며 허수아비 역산 카드의 조건과 서로 영향을 주지 않음.
- 기존 탭(`전사`, `무도가`, `메테오`)에서는 허수아비 역산 카드를 표시하지 않음.
- 입력 항목:
  - `허수아비 데미지`
  - `공격 속성`: 현재 탭의 `속공` 선택 리스트와 동일 옵션 사용
  - `대상 AC`
  - `디버프`: `호르/자보`, `콜라마`, `매프` 체크박스
- 계산 방향:
  - 허수아비 AC 100 기준 데미지를 입력받아 `허수아비 고정 AC가중치 2 * 데미지 계산 상단 데미지증가 * 데미지 계산 상단 버프가중치`로 나눠 `원 데미지`를 구함.
  - 역산 카드 상단에 `원 데미지`와 `계산된 데미지`를 함께 표시.
  - `원 데미지`를 기반으로 역산 카드에서 선택한 공격 속성 기준의 버프/디버프가중치를 다시 계산해 대상 데미지를 산출.
  - 대상 퍼센트 공식: `대상의 AC 가중치 * 데미지증가 * (버프가중치 / 디버프환산값합)`.
  - 역산 카드에도 `AC가중치`, `데미지증가`, `버프가중치`, `디버프가중치`, `퍼센트`를 별도 표기.
  - 디버프 미선택 시 `디버프환산값합`은 `1`.
  - 공격 속성 환산값이 `1 이상`이면 버프가중치에 들어감.
  - 공격 속성 환산값이 `1 이하`이면 버프 쪽 기준값은 `1`, 디버프 항목으로 들어감.
  - `호르/자보`: 환산값 `0.5`.
  - `콜라마`와 `매프`는 하나의 AC감소 디버프 그룹으로 통합 계산.
  - 콜라마/매프 그룹 환산값: `(100 + 대상 AC - 10(콜라마 체크 시) - 20(매프 체크 시)) / (100 + 대상 AC)`.
  - 디버프환산값합은 통합된 디버프/속성디버프 환산값 각각의 역수를 더한 뒤 `(적용 항목 수 - 1)`만큼 마지막에 뺌.
  - `콜라마 + 매프`만 체크 시 통합 그룹 1개로 취급하므로 `0`을 뺌.
  - `호르/자보 + 콜라마` 또는 `호르/자보 + 매프` 선택 시 `1`을 뺌.
  - `호르/자보 + 콜라마 + 매프` 모두 체크해도 통합 그룹 기준으로 `1`만 뺌.
  - `뎀감` 체크박스와 `벨트` 입력칸은 제거.

## 되돌리면 안 되는 중요 결정

- 메테오 탭에 발록을 다시 추가하지 말 것.
- 메테오 탭에 전직 항목을 다시 추가하지 말 것.
- 메테오 탭 비고 컬럼을 다시 만들지 말 것.
- 마나감소를 AC가중치에 다시 넣지 말 것.
- 트랩을 AC가중치에 다시 넣지 말 것. 트랩은 버프가중치만 영향.
- `이펙트`를 `추가속강` 명칭이나 단순 `/100` 환산으로 되돌리지 말 것. 악세와 같은 강화 환산식 사용.
- 상단 AC카드를 몬스터별 AC가중치 범위로 되돌리지 말 것. 현재는 AC 변화량 합계 표시.
- `저주`의 `데프` 환산값을 `60`으로 되돌리지 말 것. 기준값은 `50`.
- 크래셔 합계에 강한 배경색을 다시 넣지 말 것.
- 입력 중 즉시 재렌더 방식으로 되돌리지 말 것. 커서가 끊기는 문제가 있었음.
- 어빌 201 미만일 때 환산값 1 고정 규칙을 제거하지 말 것.
- 기본 몬스터를 삭제 가능하게 만들지 말 것. 삭제는 사용자가 추가한 몬스터만 가능.
- 무도가 데미지에도 `생암` 또는 `생(암)공` 속성이고 보스가 아닌 대상이면 각 기술 데미지 마지막에 `추뎀`을 더함. 허수아비도 적용 대상.
- 무도가 업글 기준 계수:
  - `붕각`: `30.52726`
  - `단각`: `20.81838`
  - `선풍`: `19.423302`
  - `지열`: 기존 `23.25` 유지
- 허수아비 `기술 계수 측정`은 `목걸이추뎀` 입력값을 별도로 받고, `허수아비가 입은 데미지 - 목걸이추뎀`을 `보정 데미지`로 사용해 역산한다.
- 기존 사용자 저장 데이터에는 `dummy.coefficient.necklaceBonus`가 없어도 기본값 `0`으로 보정되어야 한다.
- 전사/무도가의 `무장체` 스펙값을 바꿔도 수동 입력한 `추뎀` 환산값(`convManual.basePhysical`)은 초기화하지 않는다.
- 허수아비 탭에서 `전사` 또는 `무도가` 입력값 불러오기를 누르면 해당 탭의 현재 `추뎀` 환산값을 `기술 계수 측정 > 목걸이추뎀`으로 복사한다.
- 기술 계수 측정 카드의 `어빌가중치 적용`은 가중치 영역 첫 번째 그룹으로 배치해 잘 보이게 유지한다.
- 기술 계수 측정 카드의 레이아웃은 `측정값/스탯 조건`, `가중치`, `계산 결과` 순서의 grid area로 고정하고, 가중치 내부 그룹은 `auto-fit`으로 화면 폭에 맞게 4열/3열/2열/1열로 접히게 유지한다.
- 데미지 계산표는 큰 화면에서 `.app-shell` 최대 폭 `1760px`까지 사용한다. 표는 `table-layout: fixed`를 유지해 창 폭이 좁을 때도 비고까지 한 화면에 보이게 하고, 데미지 컬럼은 `min-width: 0`으로 같이 줄어들 수 있게 한다.
- 데미지 컬럼에는 inline 퍼센트 폭을 넣지 않고 `col-damage` 클래스만 부여한다. 비데미지 컬럼만 기준 퍼센트 폭을 갖고, 남는 표 폭은 데미지 컬럼이 가져가도록 유지한다.
- `1260px` 이하에서는 입력 패널과 결과 패널을 세로 배치로 전환한다. 데스크톱 모드의 최소 폭은 기존 수준을 유지한다.
- 결과표 래퍼는 `overflow-x: clip`을 유지해 가로 스크롤을 만들지 않는다. 부족한 폭에서는 일부 잘림을 허용하고, 충분한 폭에서는 `col-damage` 데미지 컬럼이 남는 폭을 받아 글자 잘림을 줄인다.
- 메테오 데미지 컬럼의 소제목과 데미지 값은 모두 중앙 정렬한다.
- 허수아비 탭의 `허수아비 역산`, `기술 계수 측정` 카드는 각각 접기/펼치기가 가능하며, 상태는 `dummy.collapsedCards.reverse`, `dummy.collapsedCards.coefficient`에 저장된다.

## 배포 안전 체크리스트

- 데미지 계산기 배포 대상:
  - Vercel/서비스 이름: `lod-cal`
  - URL: `https://lod-cal.vercel.app/`
  - GitHub 브랜치: `lod-cal`
  - 변경 파일은 기본적으로 `apps/lod-cal/**`만 포함한다.
- 키세팅 옵티마이저 배포 대상:
  - Vercel/서비스 이름: `lod-keyopt`
  - URL: `https://lod-keyopt.vercel.app/`
  - GitHub 브랜치: `lod-keyopt-github`
  - 변경 파일은 기본적으로 `lod-keyopt/**`, 키옵트 전용 `vercel.json/package.json/tools/build-static.mjs`만 포함한다.
- 절대 금지:
  - `lod-keyopt-github` 브랜치 HEAD를 그대로 `lod-cal` 또는 `main`에 push하지 말 것.
  - `lod-cal` 또는 `main` 브랜치 HEAD를 그대로 `lod-keyopt-github`에 push하지 말 것.
  - 프로젝트 이름과 브랜치 확인 없이 `git push github HEAD:lod-cal`, `git push github HEAD:main`, `git push github HEAD:lod-keyopt-github` 실행하지 말 것.
- 데미지 계산기 배포 전 필수 확인:
  - `git ls-remote --heads github lod-cal lod-keyopt-github main`로 브랜치가 각각 다른 목적의 커밋을 가리키는지 확인.
  - `git diff --cached --name-only`에 `lod-keyopt/**`가 없어야 한다.
  - `https://lod-cal.vercel.app/calculator/app.js`에는 lod-cal 최신 변경 문자열이 있어야 한다.
  - `https://lod-keyopt.vercel.app/`가 데미지 계산기 HTML을 반환하면 배포 설정이 섞인 것이므로 추가 배포 전에 중단하고 사용자에게 알려야 한다.
- 키옵트 배포 전 필수 확인:
  - `git diff --cached --name-only`에 의도하지 않은 `apps/lod-cal/**`가 없어야 한다.
  - `lod-keyopt-github` 브랜치에는 키옵트 전용 커밋만 올린다.
- 배포 실수 발생 시:
  - 먼저 `lod-cal`, `main`, `lod-keyopt-github`의 원격 커밋을 확인한다.
  - 데미지 계산기 브랜치(`lod-cal` 또는 기존 production용 `main`)에 키옵트가 섞이면 키옵트 커밋만 revert한다.
  - 키옵트 브랜치에 데미지 계산기가 섞이면 `lod-keyopt-github`를 키옵트 전용 커밋으로 복구한다.
  - 복구 후 두 URL이 서로 다른 HTML/JS를 반환하는지 확인한다.
